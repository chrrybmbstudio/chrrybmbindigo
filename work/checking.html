context

Before I took over site management, the Checking page used a paneling system from BloomCU and pushed account details into a busy PDF. This hurt scannability, accessibility, and SEO.

what I changed

  • Replaced panels with a semantic, content-rich page.
  • Built a clean CSS comparison table that lives on the page (no PDF dependency).
  • Clarified CTA hierarchy and surface area for “Open / Learn.”
  • Tuned headings, alt text, link labels, and metadata for search and a11y.
  • Designed on-page assets, including the subtle “Download the App” CSS GIF.
view live page back to work

ux / ia

  • Structured H1–H3 and section landmarks; removed duplicate headings.
  • Plan matrix: consistent labels, benefits grouped, fees surfaced plainly.
  • CTA hierarchy: primary “Open account” vs. secondary “Learn more.”
  • Improved focus states and contrast; reduced motion for users who prefer it.

content & seo

  • Rewrote microcopy for clarity; removed filler.
  • Alt text and descriptive links; title/description tuned for intent.
  • Sitemap/coverage checks + Search Console hygiene.

why it matters

  • Panels/PDFs hide content from crawlers and slow users down.
  • On-page tables improve findability, accessibility, and editing velocity.

results & recognition

Search visibility and engagement improved post-launch. Google Search Console recognized the page for performance (sample capture below). Peak period reached ≈70k clicks in 28 days (GSC).
